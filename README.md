# PiaPav — Architecture Analysis System

PiaPav — система автоматизированного статического и архитектурного анализа Python-проектов с использованием структурных метрик, графового представления исходного кода и больших языковых моделей (LLM).

Текущая версия представляет собой функциональный MVP, реализованный на основе событийной микросервисной архитектуры (Event-Driven Architecture) с использованием RabbitMQ и паттерна Choreography.

Система позволяет зарегистрировать пользователя, загрузить публичный GitHub-репозиторий, выполнить его автоматизированный анализ и получить структурированное архитектурное заключение через REST API.

## Архитектура

Система состоит из шести контейнеров:

| Компонент | Назначение |
|---|---|
| Gateway | REST API, JWT-авторизация, загрузка репозиториев, управление заявками и получение результатов |
| Parser | Статический анализ исходного кода, построение Graph DTO и Source Index |
| Metrics | Расчёт структурных, архитектурных и объектно-ориентированных метрик |
| Harness | LLM-анализ проекта с использованием специализированных инструментов и формирование заключения |
| RabbitMQ | Асинхронный обмен событиями между микросервисами |
| PostgreSQL | Хранение аккаунтов, заявок и журналов LLM-анализа |

Микросервисы взаимодействуют посредством версионированных событий RabbitMQ через exchange `analysis.events`.

Последовательность обработки:

```text
Gateway
  │ parser.start.v1
  ▼
Parser
  │ graph.ready.v1
  ▼
Metrics
  │ metrics.ready.v1
  ▼
Harness
  │ harness.completed.v1
  ▼
Gateway
```

Центральный оркестратор отсутствует. Каждый микросервис самостоятельно обрабатывает входные события и публикует результаты своей работы.

Исходный код, промежуточные артефакты и результаты анализа хранятся в общей файловой директории `/data`. Через RabbitMQ передаются события и URI артефактов, а не их содержимое.

## Запуск

### Требования

- Docker и Docker Compose.
- Настроенный API-ключ LLM-провайдера.
- Файлы конфигурации `.env`.
- Инициализированный PostgreSQL volume с базами `gateway_db` и `harness_db`.

### Конфигурация

Перед запуском необходимо настроить переменные окружения в файлах:

```text
backend/.env
backend/app/gateway/.env
```

Конфигурация включает параметры подключения к RabbitMQ, PostgreSQL, настройки JWT и LLM-провайдера.

Для создания базы данных Gateway в уже запущенном PostgreSQL:

```bash
docker compose exec postgres psql -U piapav_user -d postgres -c "CREATE DATABASE gateway_db OWNER piapav_user;"
```

Таблицы Gateway создаются автоматически при запуске приложения.

### Запуск микросервисов

Из директории `backend`:

```bash
docker compose up -d --build
```

Проверка состояния контейнеров:

```bash
docker compose ps
```

Просмотр логов:

```bash
docker compose logs -f gateway parser metrics harness
```

## REST API

| Метод | Эндпоинт | Назначение |
|---|---|---|
| POST | `/v1/auth/registration` | Регистрация пользователя |
| POST | `/v1/auth/login` | Получение JWT-токенов |
| POST | `/v1/auth/refresh` | Обновление JWT-токенов |
| POST | `/v1/project` | Создание заявки на анализ |
| GET | `/v1/project` | Получение списка проектов пользователя |
| GET | `/v1/project/{project_id}` | Получение статуса и результата анализа |
| GET | `/health` | Проверка доступности API |

### Регистрация

`POST /v1/auth/registration`

```json
{
  "name": "Test",
  "surname": "User",
  "login": "test_user",
  "password": "TestPassword123"
}
```

### Авторизация

`POST /v1/auth/login`

```json
{
  "login": "test_user",
  "password": "TestPassword123"
}
```

Ответ содержит `access_token` и `refresh_token`.

Для работы с проектами необходимо передавать access-токен в HTTP-заголовке:

```http
Authorization: Bearer <access_token>
```

При использовании Swagger UI токен можно указать через кнопку Authorize.

## Входные данные

Для запуска анализа необходимо отправить запрос `POST /v1/project`:

```json
{
  "name": "Click Architecture Analysis",
  "repository_url": "https://github.com/pallets/click",
  "branch": "main"
}
```

Обязательные параметры:

| Поле | Описание |
|---|---|
| `name` | Название проекта |
| `repository_url` | URL публичного GitHub-репозитория |
| `branch` | Название анализируемой ветки |

Gateway скачивает архив указанной ветки, сохраняет SHA коммита, регистрирует заявку в PostgreSQL и публикует событие запуска анализа.

Анализ выполняется асинхронно. После успешной отправки заявки API возвращает HTTP 202 Accepted.

## Выходные данные

Результат анализа доступен через `GET /v1/project/{project_id}`.

Возможные статусы заявки:

- `pending` — заявка ожидает завершения анализа;
- `completed` — анализ успешно завершён;
- `failed` — зафиксирована ошибка обработки.

Пример сокращённого результата:

```json
{
  "id": 1,
  "name": "Click Architecture Analysis",
  "repository_url": "https://github.com/pallets/click",
  "branch": "main",
  "status": "completed",
  "commit_sha": "08b803cf32ceb2ae6a772c62d5da42757a897d44",
  "result": {
    "issues": [
      {
        "title": "Высокая сложность метода",
        "severity": "high",
        "description": "Метод содержит сложную управляющую логику.",
        "location": "src/click/core.py:3599",
        "evidence": "Когнитивная сложность 83, цикломатическая сложность 35.",
        "recommendation": "Разделить метод на несколько специализированных функций."
      }
    ],
    "strengths": [
      {
        "title": "Умеренная средняя сложность",
        "description": "Большинство функций имеют невысокую сложность.",
        "location": null,
        "evidence": "Средняя цикломатическая сложность 2.16.",
        "recommendation": "Сохранять текущий подход к декомпозиции."
      }
    ]
  },
  "error": null
}
```

Архитектурное заключение содержит два основных раздела:

- `issues` — выявленные проблемы, уровни критичности, местоположения, доказательства и рекомендации;
- `strengths` — выявленные сильные стороны анализируемого проекта.

При формировании заключения LLM использует структурные метрики, граф зависимостей, информацию о классах, функциях и вызовах, а также специализированные инструменты доступа к исходному коду.

## Текущее состояние MVP

Реализованы и проверены:

- Регистрация и JWT-авторизация пользователей.
- Загрузка публичных GitHub-репозиториев.
- Статический анализ Python-кода без его исполнения.
- Построение Graph DTO и Source Index.
- Расчёт архитектурных и структурных метрик.
- LLM-анализ с использованием специализированных инструментов.
- Асинхронное взаимодействие микросервисов через RabbitMQ.
- Хранение заявок и журналов анализа в PostgreSQL.
- Получение результатов через REST API.
- Контейнеризация всех компонентов.

Успешно проведено сквозное тестирование на реальном Python-репозитории `pallets/click`, включающем 1306 проанализированных функций и методов.

## Ограничения текущей версии

- Поддерживается статический анализ Python-проектов.
- Поддерживаются публичные GitHub-репозитории.
- Используется локальное файловое хранилище.
- Отдельный пользовательский веб-интерфейс отсутствует.
- Количество вызовов LLM-инструментов ограничено конфигурацией.
- Политика повторной доставки событий требует дальнейшего развития.
- Результаты LLM-анализа носят рекомендательный характер и зависят от полноты статического анализа.

Текущая версия предназначена для локального запуска, демонстрации и дальнейшего развития системы.
