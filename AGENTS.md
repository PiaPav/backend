# Общие инструкции проекта

Ты работаешь с этим репозиторием автономно.

## Общие правила

- Перед внесением изменений изучай существующую архитектуру и реализацию.

- Не перерабатывай работающие компоненты без конкретной необходимости.

- Сохраняй обратную совместимость, если задача явно не требует её нарушения.

- Следуй существующему стилю кода и соглашениям проекта.

- Не изменяй файлы за пределами текущего репозитория.

- Не читай и не изменяй секреты, если это не требуется задачей.

## Политика Git

- Используй Git на протяжении работы: перед изменениями проверь состояние рабочей директории, после реализации изучи итоговый diff, а после успешных тестов и финального ревью зафиксируй результат локальным коммитом.

- Для анализа разрешены операции чтения, предусмотренные политикой OpenCode: `git status`, `git diff`, `git log`, `git show`.

- Агенты `coder`, `tester` и `reviewer` используют только разрешённые операции чтения Git и не выполняют Git-операции записи. Результаты своей работы они передают агенту `orchestrator`.

- Агент `orchestrator` после успешного тестирования и финального ревью обязан проверить итоговый diff, добавить в индекс только относящиеся к текущей задаче файлы с помощью `git add` и создать локальный коммит с помощью `git commit`.

- Перед `git add` и `git commit` агент `orchestrator` обязан убедиться, что в коммит не попадут посторонние пользовательские изменения, сгенерированные файлы, секреты или иные файлы вне области задачи.

- Каждую Git-команду выполняй отдельным вызовом Bash. Не объединяй несколько Git-команд в одну строку.

- Не выполняй без явного требования пользователя другие операции, изменяющие состояние Git: `reset`, `checkout`, `switch`, `branch`, `merge`, `rebase`, `cherry-pick`, `stash`, `tag`, `update-ref` и аналогичные.

- Push и любые другие операции записи в удалённый репозиторий запрещены для всех агентов, в том числе для `orchestrator`. Запрещены force push, удаление веток и переписывание истории.

- Не выполняй несвязанный с задачей рефакторинг.

## Порядок разработки

Для каждой существенной задачи:

1. Проанализируй репозиторий и текущую реализацию.

2. Определи затрагиваемые компоненты.

3. Сформируй план реализации.

4. При необходимости используй специализированных субагентов.

5. Реализуй изменение.

6. Добавь или обнови тесты.

7. Запусти релевантные тесты.

8. Проверь итоговый diff.

9. Проведи независимое ревью.

10. Исправь обнаруженные существенные проблемы.

11. Повторно запусти необходимые проверки.

12. После успешных тестов и ревью агент `orchestrator` проверяет итоговый diff, добавляет в индекс только файлы текущей задачи и создаёт локальный коммит.

Задача не считается завершённой, пока реализация и проверка не закончены.

Не останавливайся на этапе предложения решения или написания плана, если пользователь запросил реализацию.
