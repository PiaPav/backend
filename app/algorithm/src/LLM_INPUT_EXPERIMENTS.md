# Варианты тестирования графов и метрик с LLM

Профили ниже соответствуют плану `DATA_PROFILES_PLAN.md`. Все Graph View должны строиться из одного `canonical.full`, а Metrics View — копироваться из метрик, рассчитанных по полному графу.

| Вариант входа | Что получает модель | Ожидаемый результат |
|---|---|---|
| `metrics.overview` | Размер, активность и основные агрегаты без топологии | Быстрая общая оценка; слабая объяснимость и локализация проблем |
| `aggregate.overview` + `metrics.overview` | Компактная карта проекта, resolution coverage и top-k | Лучший дешёвый стартовый контекст; выводы остаются обзорными |
| `structure.declarations` + `metrics.quality` | Дерево владения и показатели сложности | Поиск сложных файлов и callable с пониманием их места в структуре; почти без анализа связности |
| `dependency.architecture` + `metrics.architecture` | Файловые/package-зависимости, циклы, coupling и centrality | Аргументированные выводы о границах модулей, циклах и архитектурных узлах риска |
| `calls.topology` + `metrics.calls` | Взвешенный call graph, рекурсия, цепочки, reachability и hotspots | Поиск критических путей и вызываемых центров; без доказательств на уровне отдельных callsite |
| `calls.detailed` + `metrics.calls` | Call graph, все callsite, выражения, координаты и complexity facts | Наиболее точная диагностика вызовов и hotspots, но заметно больший контекст |
| `types.topology` + `metrics.objects` | Наследование, типы полей и объектные показатели | Анализ иерархий и части OO-дизайна; недостаточно данных для объяснения CBO/RFC/LCOM/WMC |
| `objects.metrics_basis` + `metrics.objects` | Полная доказательная база текущих объектных метрик | Объяснимые выводы по DIT/NOC/CBO/RFC/LCOM/WMC и связанности классов |
| `structure.declarations` + `dependency.architecture` + `calls.topology` + соответствующие Metrics View | Несколько согласованных представлений одного графа | Лучший баланс покрытия и объёма для комплексного архитектурного ревью; нужно исключать дублирование данных |
| `canonical.full` + `metrics.full` | Все доступные структуры, связи, occurrences, diagnostics и метрики | Эталон полноты для сравнения вариантов; максимальная стоимость и риск информационного шума |
| `inventory.minimal` + `metrics.overview` + инструменты по требованию | Минимальный стартовый контекст с дозагрузкой структуры, связей, метрик и кода | Наилучшая потенциальная экономия контекста; качество зависит от способности модели вовремя запросить нужные данные |

## Схема эксперимента

- На одинаковых проектах и вопросах сравнить: только граф, только метрики, согласованную пару и режим дозагрузки.
- Использовать одинаковые модель, системный prompt и лимит ответа.
- Оценивать полноту найденных проблем, точность, наличие проверяемых доказательств, ложные выводы, расход токенов, число вызовов инструментов и задержку.
- Считать вывод подтверждённым только при ссылке на конкретную метрику, node/edge либо участок исходного кода; отсутствие связи в reduced view нельзя трактовать как отсутствие связи в проекте.
