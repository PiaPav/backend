# Поисковый индекс исходного кода

## Назначение

Во время анализа рядом с графом и метриками создаётся `source_index.json`. Он
связывает файлы и Python-структуры с точными диапазонами исходного кода. Сам
исходный код в индекс не копируется.

Индекс предназначен для следующего отдельного шага системы: по известным имени
файла, классу и методу быстро найти координаты, а затем прочитать нужный диапазон
из исходного файла. Реализация этого поиска в парсер не входит.

Публичный `graph.json` при добавлении индекса не изменяется.

## Как индекс строится

Каждый `.py`-файл по-прежнему читается один раз и разбирается одним вызовом
`ast.parse`. Индекс наполняется одновременно со сбором определений для графа:
тот же проход по верхнему уровню `ast.Module` регистрирует классы, методы,
функции, поля класса и присваивания уровня модуля. Дополнительного прохода по
AST для поискового файла нет.

После сбора выполняется только сериализация уже подготовленных словарей в JSON.

## Верхний уровень

```json
{
  "schema_version": 1,
  "project": {},
  "files_by_name": {},
  "files": {},
  "symbols": {},
  "lookup": {}
}
```

### `project`

- `root` — абсолютный корень проекта на момент анализа;
- `fingerprint` — SHA-256 от отсортированных пар `относительный путь + хеш файла`;
- `file_count` — количество проанализированных Python-файлов.

`fingerprint` позволяет связать индекс с конкретным состоянием исходников. Перед
выдачей кода будущий поисковый сервис должен дополнительно сверять `sha256`
нужного файла.

### `files_by_name`

Прямой индекс по базовому имени файла:

```json
{
  "storage.py": [
    "infrastructure/storage.py",
    "legacy/storage.py"
  ]
}
```

Значением всегда является список, потому что в разных каталогах могут находиться
одноимённые файлы. Получение кандидатов по `storage.py` — операция словаря
`O(1)`, не требующая обхода секции `files`.

### `files`

Ключ — относительный POSIX-путь от корня анализа:

```json
{
  "infrastructure/storage.py": {
    "relative_path": "infrastructure/storage.py",
    "name": "storage.py",
    "module": "infrastructure.storage",
    "sha256": "...",
    "size_bytes": 4312,
    "encoding": "utf-8",
    "classes": {
      "Storage": ["infrastructure/storage.py::class:Storage@8"]
    },
    "functions": {},
    "constants": {}
  }
}
```

Карты `classes`, `functions` и `constants` дают быстрый переход от файла и имени
к `source_id`. Значения являются списками: Python допускает повторное объявление
одного имени, и индекс не должен молча терять такие определения.

### `symbols`

Нормализованное хранилище структур. Данные структуры записываются здесь один раз,
а остальные секции содержат только её `source_id`.

```json
{
  "infrastructure/storage.py::method:Storage.get@21": {
    "source_id": "infrastructure/storage.py::method:Storage.get@21",
    "kind": "method",
    "name": "get",
    "qualified_name": "Storage.get",
    "file": "infrastructure/storage.py",
    "parent_id": "infrastructure/storage.py::class:Storage@8",
    "span": {
      "start_line": 20,
      "start_column": 4,
      "end_line": 27,
      "end_column": 20,
      "start_byte": 418,
      "end_byte": 693
    }
  }
}
```

Поддерживаемые `kind`:

- `class` — класс верхнего уровня;
- `method` — непосредственный метод класса;
- `function` — функция верхнего уровня;
- `field` — присваивание поля непосредственно в теле класса;
- `constant` — именованное присваивание уровня модуля.

У символа класса дополнительно есть карты `methods` и `fields`, также содержащие
списки `source_id`.

### `lookup`

Готовые составные ключи для наиболее частых запросов:

```json
{
  "classes": {
    "infrastructure/storage.py::Storage": ["..."]
  },
  "methods": {
    "infrastructure/storage.py::Storage::get": ["..."]
  },
  "functions": {
    "infrastructure/storage.py::create_storage": ["..."]
  },
  "constants": {
    "infrastructure/storage.py::DEFAULT_TIMEOUT": ["..."]
  }
}
```

После разрешения базового имени `storage.py` в точный относительный путь запрос
метода состоит из двух словарных обращений:

1. `lookup.methods["infrastructure/storage.py::Storage::get"]` возвращает
   кандидатов `source_id`;
2. `symbols[source_id]` возвращает файл и точный `span`.

Поиск не перебирает файлы или структуры, поэтому стоимость разрешения ключа в
среднем постоянна. Чтение самого фрагмента неизбежно занимает время,
пропорциональное размеру возвращаемого кода.

## Координаты

- строки нумеруются с `1`;
- колонки нумеруются с `0`;
- конец диапазона исключающий;
- `start_byte` и `end_byte` — смещения в байтах физического UTF-8-файла;
- диапазон начинается с синтаксической границы AST (`def`, `class`, имя
  присваивания), поэтому предшествующий ей отступ строки в диапазон не входит;
- если структура декорирована, диапазон начинается с символа `@` первого
  декоратора;
- BOM UTF-8, если он присутствует, учитывается в byte-offset.

Будущий получатель кода может открыть файл в бинарном режиме, перейти на
`start_byte` и прочитать `end_byte - start_byte` байт. Это не требует повторного
разбора AST или чтения файла по строкам.

Для получения файла целиком достаточно записи `files[relative_path]`: путь
определяет файл, а `size_bytes` — ожидаемый размер.

## Проверка актуальности

Перед чтением кода рекомендуется:

1. соединить доверенный корень анализа и `relative_path`;
2. убедиться, что итоговый путь остаётся внутри корня;
3. вычислить SHA-256 файла;
4. сравнить его с `files[relative_path].sha256`;
5. при несовпадении не применять сохранённые byte-offset и потребовать повторный
   анализ.

Абсолютный путь из пользовательского запроса нельзя использовать напрямую.
Пользователь задаёт имя или относительный путь, а физический путь формируется
только из доверенных данных индекса.

## Публичный API построения

`starter(input_project)` остаётся без изменений и возвращает только граф.

`starter_with_source_index(input_project)` выполняет тот же единый анализ и
возвращает пару:

```python
graph, source_index = starter_with_source_index(project_path)
```

`save_source_index(source_index, output_path)` сохраняет индекс в UTF-8 JSON.
Общая точка запуска `build_project_graph()` автоматически создаёт
`source_index.json`; путь можно переопределить аргументом `output_source_index`.
