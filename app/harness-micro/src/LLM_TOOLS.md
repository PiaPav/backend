# Инструменты исследования исходного кода

## Исходный код

| Инструмент | Описание |
|---|---|
| `GET-CONTENT <FILEPATH>` | Получить полное содержимое файла. |
| `GET-STRUCTURE <FILEPATH> <STRUCTURE-TYPE> <STRUCTURE-PATH>` | Получить исходный код указанного класса, функции или метода. |
| `GET-CODE-RANGE <FILEPATH> <START-LINE> <END-LINE>` | Получить заданный включительный диапазон строк файла вместе с номерами строк. |

## Граф проекта

| Инструмент | Описание |
|---|---|
| `GET-GRAPH <PROFILE-ID>` | Получить выбранный вариант графа проекта. |
| `FIND-GRAPH-NODES <QUERY> [KIND] [PATH] [LIMIT]` | Найти объекты в `canonical.full` по имени с необязательной фильтрацией по виду и файлу. |
| `GET-GRAPH-NODE <NODE-ID>` | Получить подробные сведения об объекте из `canonical.full`. |
| `GET-GRAPH-SUBGRAPH <PROFILE-ID> <NODE-ID> <DEPTH> [RELATION-TYPE] [DIRECTION]` | Получить ограниченный подграф вокруг объекта. `DIRECTION` принимает `incoming`, `outgoing` или `both`. |
| `GET-GRAPH-REFERENCES <OWNER-NODE-ID> [REFERENCE-TYPE] [STATUS]` | Получить ссылки, принадлежащие объекту, включая однозначные, неоднозначные и неразрешённые случаи. |

`GET-GRAPH-SUBGRAPH` поддерживает `canonical.full` и node/edge graph views,
перечисленные в `GRAPH_RELATION_TOOLS_CONTRACT.md`. `DEPTH=0` возвращает seed и
его self-loops. Обход выполняется BFS после фильтрации `RELATION-TYPE`;
`DIRECTION` влияет на достижимость, а результат содержит полный induced набор
рёбер между выданными узлами. Узлы ограничиваются настроенным лимитом, counts и
`completeness` сообщают полные и возвращённые количества узлов и рёбер.

`GET-GRAPH-REFERENCES` читает `canonical.full`. `REFERENCE-TYPE` принимает
`call`, `import` или `type`, `STATUS` — `exact`, `ambiguous`, `external`,
`dynamic` или `unresolved`. Возвращаются только непосредственно принадлежащие
узлу occurrences; кандидаты неоднозначной ссылки не считаются точными целями.

## Показатели

| Инструмент | Описание |
|---|---|
| `GET-METRICS <PROFILE-ID>` | Получить выбранный набор рассчитанных показателей проекта. |
| `GET-METRICS-ITEM <PROFILE-ID> <METRIC-PATH>` | Получить отдельный показатель или раздел выбранного профиля. `METRIC-PATH` задаётся как JSON Pointer. |

`GET-METRICS-ITEM` выбирает профиль по точному непустому `PROFILE-ID` и применяет
RFC 6901 JSON Pointer к фактическому корню JSON: пустой путь возвращает корень.
Значения возвращаются без преобразования табличных `$columns`/`$rows`, поскольку
их DTO-контракт на этом этапе неоднозначен. Fragment-форма `#` не поддерживается.

### Поиск и получение узлов `canonical.full`

`FIND-GRAPH-NODES` требует непустой `QUERY` (пробелы не удаляются) и ищет его
`casefold()`-подстрокой в `qualified_name` без Unicode-нормализации и дедупликации.
`KIND` и `PATH` — точные фильтры, соединённые с поиском через AND; `PATH`
регистрозависим и является относительным POSIX-путём. Результаты сортируются по
`(qualified_name.casefold(), qualified_name, id)`. `LIMIT` равен 20 по умолчанию,
настраивается до общего максимума 100. `total` считается до ограничения.

`GET-GRAPH-NODE` выполняет точный регистрозависимый поиск по непустому `NODE-ID`
и возвращает исходный объект целиком. Оба инструмента сообщают профиль
`canonical.full`; неизвестный ID — ошибка `node_not_found`, отсутствующий профиль
— `profile_not_found`. Повреждённый граф — `invalid_artifact`. Общий байтовый
лимит ответа возвращает `extraction_limit_exceeded`, не обрезая JSON или узел.

## Общие правила

- Профиль выбирается по точному `PROFILE-ID` из
  `GRAPH_AND_METRICS_PROFILES.md`; алиасы и версии профилей не используются.
- Для неизвестного профиля, объекта, пути или значения аргумента инструмент
  возвращает структурированную ошибку, а не пустой результат.
- Ответ сохраняет канонические идентификаторы объектов и сообщает профиль,
  из которого получены данные.
- Ответ явно содержит признаки обрезки и неполноты, а также количество
  найденных и возвращённых элементов.
- Предположительные, неоднозначные и неразрешённые связи не выдаются за
  достоверные.
- `DEPTH`, `LIMIT`, размер диапазона исходного кода и общий размер ответа
  ограничиваются настройками харнесса.
